# Foundation Console v0.2.0 更新日志

> 发布日期：2026-11-13（UTC+8）
> 仓库：DNT-118/FoundationConsole · 许可证：Apache-2.0 · 作者：DNT_OF（DNTOF）
> 对接上游：SLDataAPI main（2.6.x，建议 2.6.0 PEAK 及以上）
> 运行环境：Node.js **22.14+**（推荐 24）

v0.2.0 是 Foundation Console（FDC）开源后的第一个正式发布版本。它用「React 前端 + Node.js 后端」的完整平台取代了 v0.1.0 的纯浏览器控制台，对齐了 SLDataAPI 2.6.x 的现有接口，新增团队协作（服务器成员、通知、定时任务、玩家历史），完成了一轮全面安全审计，并开始提供带 Ed25519 签名的发布包。

## 1. 定位变化：自部署的私有内部管理平台

- FDC 不再作为公共托管平台运营。从 v0.2.0 起，它的定位是**服主团队自部署的私有内部管理平台**：部署在团队自己的服务器上，账户、服务器配置、分享与权限都只属于你自己的部署实例。
- README、`docs/README.md`、`docs/security.md` 已按这一定位改写。安全设计以「团队内部可信 + 上游 SLDataAPI ACL」为前提；对公网暴露时请配合反向代理、HTTPS，并按需关闭自助注册。
- 平台不含遥测或统计上报；所有凭据只保存在部署者自己的数据目录里，作者和任何第三方都接触不到。
- 新增的成员分享只面向同一部署实例内的平台账户，没有任何跨实例或公共目录语义。
- 在线演示（GitHub Pages）是独立的 `pages-demo` 分支：数据只存在浏览器本地，没有后端，部分功能不可用，不代表正式版能力。

## 2. 平台架构：从纯前端到前后端一体

v0.1.0 是只在浏览器里运行的控制台，浏览器直接持有游戏服令牌。v0.2.0 改为完整平台：

**后端（`server/`，Node.js）**
- 认证：注册、登录、会话（服务端存储，7 天过期）、可选 TOTP 双因素验证（含同窗口防重放）。
- 三级平台权限：`admin` / `user` / `guest`，后端强制校验；首个注册的账户自动成为管理员，此引导只发生一次。
- 按用户隔离的服务器配置，支持多台游戏服务器。
- 管理员设置：用户管理、公告、SMTP、Steam Key、注册模式、玩家历史保留天数等。
- SLDataAPI 代理：数据口（`GET /get_sl_data`、`/plugins/*`）、控制口（`POST /control/*`）、控制 WebSocket、语音 WebSocket 全部经后端转发；VerifyToken / API Key 只由后端注入，浏览器只访问同源 `/api`，不持有游戏服凭据。
- 敏感配置（游戏服 VerifyToken / API Key、SMTP 凭据、Microsoft refresh token、Steam Key、TOTP Secret）以 AES-256-GCM 加密保存，主密钥为 `server/data/master.key` 或环境变量 `PFC_MASTER_KEY`。
- 密码使用 scrypt 加盐哈希；非管理员不能把服务器指向私网地址；控制路径走严格白名单。
- 运行数据目录默认 `server/data/`（可用 `PFC_DATA_DIR` 修改），首次启动自动创建，已在 `.gitignore` 中排除。

**前端（`src/`，React 19 + Vite）**
- 页面：Dashboard、服务器、玩家、插件、地图、日志、举报、事件、封禁列表、文件、控制台、RemoteAdmin、语音、公告、API 文档、设置、关于，以及 v0.2.0 新增的通知中心和定时任务。
- WebSocket 实时状态与控制通道，连接失败时自动回退 HTTP。
- 中英文界面，主题切换。

**部署**
- `build-package.sh` 生成 `release/fdc-v<版本>.tar.gz`（前端 `dist/` + 混淆后的后端），发布包内不含任何运行数据；打包时会兜底检查，发现 `master.key`、`*.pem`、`users.json`、`sessions.json` 即中止。
- 安装脚本：Linux `install.sh`（安装依赖、生成主密钥、注册 systemd 服务）、Windows `install.ps1`，附 `pfc.service` 模板。
- 文档：`docs/architecture.md`、`docs/data-and-backup.md`、`docs/local-development.md`、`docs/peak-maintenance.md`、`docs/security.md`、`docs/slapi-contract-addendum.md`、`docs/ws-control-design.md`。

## 3. SLDataAPI 2.6.x 同步

FDC 原先对接 SLDataAPI 2.6.0 PEAK，本版本对齐到 SLDataAPI main 的现有接口。**只实现上游源码中确实存在的路由与字段**，前端调用的每个 `/control/*` 端点都已与上游逐一核对。完整对照表见仓库中的 `SYNC-REPORT.md`。

### 3.1 鉴权

- 数据口使用 `verify_token`，控制口、控制 WS、语音 WS 使用 API Key，均以 `Authorization: Bearer` 注入，与上游一致。
- 上游 2.6 已不再接受 `X-Control-Token`、`?token=`、`?key=`，FDC 不使用这些旧方式。

### 3.2 新增数据字段（`/get_sl_data`）

- `game_version`：游戏版本，显示在仪表盘「API 健康度」卡；旧服务端缺省显示「—」。
- `active_holiday`：当前节日，本地化显示（无 / 圣诞节 / 万圣节 / 愚人节）。
- `adapted_plugins[].actions`：适配插件可执行的动作（上游开启内测后才返回）。

### 3.3 新增控制功能

| 上游路由 | FDC 位置 | 说明 |
|---|---|---|
| `/control/round/wave` | 远程管理 | 查询九尾狐 / 混沌重生波次状态、立即重生、设置倒计时与代币 |
| `/control/dummies` | 远程管理 | 生成假人（昵称、可选职业）、列表（10 秒轮询）、移除单个或全部；显示 `count/max` |
| `/control/player/inventory` | 远程管理 | 物品栏添加 / 移除 / 清空（可含弹药） |
| `/control/player/candy` | 远程管理 | 发放 SCP-330 糖果（指定名称或随机，最多 6 个） |
| `/control/map/status` | 地图 | 「设施状态」只读卡片：回合统计、去污、发电机、核弹、SCP-914、节日糖果池，30 秒轮询 |
| `/control/adapted/<plugin_id>/<action>`（内测） | 插件 | 对带 `actions` 的适配插件执行动作，可附 JSON 请求体并查看结果；后端白名单按两段制放行，拒绝 `..` 等异常路径 |
| `/control/player/data` | 玩家 | 只读「玩家档案」面板（见 4.6） |
| `/control/files/stat · read_chunk · write_chunk`（内测） | 文件 | 分块读写（见 4.7） |

`/control/moderation/mute` 的 `mute_scope` / `persistent` 字段已补入 API 文档页；API 文档页端点从 23 条扩充到 37 条，并更正了「inventory / dummies 未实现（501）」等过时说明。

### 3.4 控制 WS 事件对齐（12 种真实事件）

事件页原先监听的 `player_joined`、`player_left`、`player_died`、`elevator_used`、`door_opened`、`round_started`、`round_ended` 上游从不推送。现已对齐上游 WsEventBridge 实际推送的 12 种事件，并按各事件字段重写了中英文摘要：

`player_banned`、`player_kicked`、`player_escaped`、`player_role_changed`、`player_reported`、`wave_respawned`、`decontamination_started`、`generator_activated`、`scp_terminated`、`warhead_started`、`warhead_stopped`、`warhead_detonated`

### 3.5 结构化错误

新增 `ControlError`，HTTP 与 WS 两条控制链路统一抛出，并给出本地化提示：

| 上游错误 | FDC 提示 |
|---|---|
| `409 holiday_inactive` | 「节日功能未开启：需要 X，当前节日为 Y」，用于物品、糖果、效果等入口 |
| `501 feature_unavailable` | 「当前游戏版本不提供该功能」 |
| `426 tls_required` | 提示改用 HTTPS / WSS |
| `404 transport_mismatch` | 平台自动切换传输方式并重试同一次调用（原有） |
| `403` | 如实透传上游「API Key 有效但未授权该端点」 |

### 3.6 混沌分裂者独立成队

- 上游玩家列表中的 `混沌`（ChaosInsurgency）现在映射为独立的 `Chaos` 队伍，不再并入 D 级；`其他`（OtherAlive）映射为 Unknown。
- 上游 `d_count` 是 D 级与混沌的合计，FDC 按玩家列表拆出混沌人数：`D 级 = d_count − 混沌人数`（钳制为非负）。
- 玩家页混沌以绿色显示；地图页混沌玩家点与图例为 `#2ECC71`；仪表盘队伍分布卡由 4 格扩为 5 格，新增「混沌分裂者」。

## 4. 团队协作与运维功能

### 4.1 服务器成员与权限

- 服务器新增 `owner`（创建者）与成员列表，成员角色分 `viewer`（只看数据）、`operator`（值班）、`manager`（管理）三级，加上所有者共四级。

| 角色 | 读取数据 | 控制调用 / 语音 / 事件流 | 成员管理 / 定时任务 | 修改配置 / 删除服务器 |
|---|---|---|---|---|
| owner | ✅ | ✅ | ✅ | ✅ |
| manager | ✅ | ✅ | ✅ | ❌ |
| operator | ✅ | ✅ | ❌ | ❌ |
| viewer | ✅ | ❌ | ❌ | ❌ |

- 每一层都在服务端独立校验：HTTP 控制调用、WS 控制中继、事件订阅、语音升级以及 WS 定期清扫，不只靠前端隐藏。成员被移除后，数据、控制、语音、事件访问立即撤销。
- manager 不能授予或移除 manager，不能改动其他 manager 的角色，不能动 owner；成员必须是本实例已有的平台账户。
- 非 owner（包括平台管理员）不能修改或删除不属于自己的服务器配置。
- 角色只决定 FDC 内的访问范围，不改变 SLDataAPI Key 本身的权限；上游 ACL 照常生效。
- 前端：服务器卡显示「已共享 · 角色」徽标；删除按钮只对 owner 显示并带确认；owner / manager 可展开成员面板添加、改角色、移除成员。

### 4.2 通知规则与通知中心

- 新页面「通知中心」（侧栏铃铛图标）。
- 规则可选服务器（或全部可访问的服务器）、12 种事件的任意子集、站内 / 邮件通道、最小间隔（10–3600 秒），可启用 / 停用；每个用户最多 20 条规则。
- 频率限制与去重：同一规则同一事件在最小间隔内只发一次；同一用户相同事件与内容 60 秒内跨规则去重；邮件通道对每个用户另有 60 秒间隔。
- 站内通知进入收件箱（每个用户保留最近 100 条），支持未读高亮、全部已读、清空，30 秒轮询。
- 邮件通道仅管理员规则可用（服务端强制），经已配置的 SMTP 发往用户注册邮箱。
- 通知处理与事件转发相互隔离，通知出错不会影响事件流。

### 4.3 定时任务

- 新页面「定时任务」（时钟图标）。
- 任务类型只使用上游已有的控制端点：全服广播（`/control/broadcast`）、CASSIE（`/control/cassie`）、控制台命令（`/control/console/command`）。
- 内容按上游约定校验：广播最多 500 字符、时长 1–60 秒；CASSIE 最多 2000 字符；控制台任务禁止 `sldataapi` / `slda` 管理命令。
- 间隔 60 秒到 7 天；全实例最多 50 个任务；每个任务保留最近 20 条执行记录，可在列表中展开查看。
- 调度器每 15 秒检查一次，单次执行 30 秒超时，同一轮内不会重复执行同一任务；执行走与人工操作相同的控制中继，继承上游 ACL。
- 状态持久化到 `schedules.json`：服务重启后按原节奏继续，停机期间错过的执行最多补跑一次；暂停后恢复时从当前时间重新计时，不会补跑。
- 仅 owner / manager 可以创建、修改、暂停、恢复、删除任务。每次执行前都会重新核对创建者的权限：创建者被移出服务器、降到 manager 以下或账号被删除后，任务会跳过执行并记录失败。

### 4.4 玩家历史（默认保留 30 天）

- 后端在每次成功轮询 `/get_sl_data` 后做差分，记录玩家进出会话：新出现的玩家记为进入，消失的玩家记为离开并计算时长，改名会跟随。
- 只记录 Steam 玩家（`@steam` 后缀会被剥除）；`@northwood`、`@discord` 与假人不记录。只保存 SteamID 与昵称（昵称截断到 64 字符），不记录 IP。
- 保留天数默认 30 天，管理员可在 1–365 天之间调整，过期数据自动清理；管理员可按服务器或全部清除历史。
- 玩家页新增「在线 / 历史」视图切换：历史视图包含在线人数趋势折线图（2 天内 30 分钟一档、7 天内 2 小时一档、更长按天）和按玩家聚合的表格（昵称、SteamID、会话数、总时长、最近在线、是否在线）。
- 数据保存在 `server/data/playerHistory.json`，查询按服务器访问权限过滤。

### 4.5 多服务器总览

仪表盘「全部服务器」卡升级为总览表，每台服务器一行，显示：健康状态（数据 30 秒内为绿、过期为黄、离线为红）、在线人数、回合阶段、回合时长、核弹状态和 TPS。上游目前不提供 TPS，因此显示「—」并提示「上游未提供」。

### 4.6 玩家档案面板

- 玩家卡片头部新增入口，打开只读的玩家档案（`POST /control/player/data`）。
- 只显示上游真实返回的字段：已知的 30 个字段（生命、护盾、体力、物品、弹药、效果、TemporaryBypass、语音频道、是否假人等）按固定顺序双语标注，值为空的字段跳过；上游新增的未知字段按原样 JSON 展示，不丢信息。
- 支持 Esc 和点击遮罩关闭，带 `role="dialog"` / `aria-modal`。

### 4.7 文件分块读写与 SHA-256 校验

需要游戏服开启上游内测 `beta_file_root_ws`：

- 分块读取：每块 64KB，循环到 `eof`；校验偏移连续性和长度；用首帧附带的整文件 `sha256` 核对本地拼接结果；单文件上限 1MB（与上游一致）。
- 分块上传：每块原始数据 32KB；最后一块附带整份内容的 `sha256`，并核对上游返回的提交结果；失败或取消时向上游发送 `abort` 释放上传会话；单文件上限 512KB，客户端预检。
- 内置纯 JS SHA-256 实现，局域网明文 HTTP 下（`crypto.subtle` 不可用）同样可用，已用 FIPS 180-4 标准向量做回归测试。
- 文件页编辑器在上游声明支持分块时显示「分块读取」「分块保存」按钮、字节进度条和取消按钮；状态栏显示本地内容的 sha256。平台本身不落盘任何文件内容，只做中继。

### 4.8 控制 WS 能力信息

- 平台读取上游控制 WS 握手 `hello` 中的 `version`、`beta`、`tls`、`cert_fingerprint`，推送给订阅该服务器的浏览器。
- 仪表盘「API 健康度」卡显示上游版本、本连接是否 TLS、证书 SHA-256 指纹和已开启的内测能力（`adapted_actions` / `file_chunks`）。仅在使用 WS 控制通道时可知；HTTP 回退模式显示「未知（需 WS 控制通道）」。
- 内测能力未开启时，插件页的适配插件动作区和文件页的分块区会直接给出提示，而不是点了才返回 404。

## 5. 账户、注册与邮件

### 5.1 注册模式与邀请码

- 管理员可在「设置 → 注册模式」切换三种模式：
  - `open`（出厂默认）：QQ 邮箱自助注册 + 邮箱验证码，行为与以前一致；
  - `invite`：自助注册需要管理员签发的一次性邀请码；
  - `closed`：关闭自助注册，由管理员在账号管理中建号。
- 三种模式都只允许 QQ 邮箱；首个管理员的引导注册不受模式影响；切换模式只影响新注册，已有账户和会话不受影响。
- 邀请码以 `inv_` 开头，明文只在创建时显示一次，列表中脱敏显示，可吊销；只有在全部校验通过后才会被消费，验证码输错不会浪费邀请码；未使用的邀请码最多 20 个。
- 注册页按当前模式显示关闭提示或邀请码输入框；`/api/auth/status` 返回 `registrationMode`。
- 内部部署建议上线后改为 `invite` 或 `closed`。

### 5.2 Microsoft Entra ID 设备代码流（SMTP XOAUTH2）

Outlook / Office 365 发信的 OAuth2 授权已重做，适合管理员在远程公网控制台操作、没有 localhost 回调的场景：

- 默认使用**设备代码流**：在「设置 → 邮箱配置 → OAuth2」点「连接 Microsoft 账号」，打开 microsoft.com/devicelogin 输入页面显示的用户码，授权完成后自动加密保存，无需再点保存。设备码会话绑定发起的管理员，30 分钟过期。
- 内置多租户公共客户端（`PFC_MS_CLIENT_ID` 默认值，非机密，可覆盖），租户默认 `common`，个人 Microsoft 账户和工作 / 学校账户都能用，其他人只需要一个 Microsoft 账户。
- scope：`https://outlook.office.com/SMTP.Send offline_access openid email profile`（可用 `PFC_MS_SCOPES` 覆盖）。
- SMTP 主机按 id_token 的 `tid` 自动选择：个人账户使用 `smtp-mail.outlook.com:587`，组织账户使用 `smtp.office365.com:587`；主机可手动覆盖，端口固定 587。
- 可选的授权码 + PKCE 跳转流程：配置 `PFC_MS_REDIRECT_URI`（或由 `PFC_PUBLIC_URL` 推导）后，设置页出现「跳转授权」按钮；state 绑定管理员会话、一次性、10 分钟过期；回调地址只来自这两个环境变量，从不使用请求的 Host 头。只有机密客户端才需要 `PFC_MS_CLIENT_SECRET`。
- refresh token 用 `master.key` 加密落盘，每次刷新自动轮换写回；access token 只在内存缓存；授权失效（`invalid_grant`）时设置页提示「需要重新授权」。nodemailer 只使用现成的 access token，不会自行请求令牌端点。
- SMTP 设置接口改为安全视图：只返回「是否已配置」等布尔值和账户邮箱，从不返回明文凭据或令牌。保存表单时密码留空表示保留原值，勾选「清除已保存的授权码」才会删除；测试发送始终使用已保存的配置。
- 普通 SMTP（授权码 / 密码）模式保持不变。
- 新环境变量：`PFC_MS_CLIENT_ID`、`PFC_MS_TENANT`、`PFC_MS_CLIENT_SECRET`、`PFC_MS_REDIRECT_URI`、`PFC_MS_SCOPES`（见 `.env.example` 与 README）。

### 5.3 注册流程

- 错误检查顺序修正：先检查邮箱格式与频率限制，再提示「SMTP 未配置」。
- 同一个邮箱验证码连续输错 5 次即作废（发码侧原有 60 秒冷却和按 IP 的小时 / 每日配额）。

## 13. 已知限制

以下事项已在安全审计中评估，在「团队内部可信」的部署前提下风险较低，本版本暂未修改，后续版本可能继续加固：

- **F5**：成员管理、通知规则、玩家历史等需要登录的管理类路由尚无统一限流（登录、发码、2FA、验证码等对外入口已有限流与锁定）。
- **F6**：账号连续登录失败会被临时锁定 5 分钟，在共享公网出口下可能互相影响。
- **F7**：发送注册验证码时会提示「该邮箱已注册」。
- **F8**：`master.key` 直接派生加密密钥，未使用慢速 KDF；数据文件的 0600 权限在 Windows 上不生效，请用系统 ACL 限制数据目录访问。
- **F9**：平台到游戏服的数据、控制与语音连接为明文 HTTP / WS，暂不支持 wss，上游设置为 `tls_mode: required` 的游戏服无法连接；建议部署在局域网或专线，或使用 `tls_mode: optional`。
- **F10**：CSP 的 `style-src` 允许 `'unsafe-inline'`（主题与背景大量使用内联样式；脚本策略不受影响）。
- **F11**：会话令牌与邀请码以随机值形式保存在权限为 0600 的数据文件中，未做哈希。
- **F12**（信息级）：Steam 资料接口对非 Steam ID 返回 400、查无此人返回 404，仅反映 Steam 状态，不涉及平台账户信息。

其他：

- 上游不提供 TPS，多服务器总览中显示「—」。
- 玩家历史基于轮询差分，轮询间隔内瞬进瞬出可能记录不到或时长偏短。
- 混沌人数按玩家列表拆分，极端情况下（有未分配职业的玩家）可能有 ±1 的误差。
- 定时任务在服务重启后最多补跑一次错过的执行。
- 在线演示（`pages-demo`）为纯前端演示，与本版本功能不完全一致。
