# 0.2.0：SLDataAPI 2.6.0 PEAK 适配与维护

## 兼容基线

- 发布版本：[v2.6.0_PEAK](https://github.com/DNTOF/SLDataAPI/releases/tag/v2.6.0_PEAK)。
- 0.2.0 适配时参考的 SLDataAPI 提交为 [`1f6869b`](https://github.com/DNTOF/SLDataAPI/commit/1f6869b66981906e2d821c758a4d15620da3bbc1)；相对发布标签仅 README 有差异，接口代码一致。本仓库不再内嵌 SLDataAPI 子模块，请直接参考上游仓库。
- Node.js 最低 22.14；生产推荐 Node 24，CI 验证 22 / 24。
- 平台版本 `0.2.0`。游戏服和平台分别更新；平台不会自动替换游戏服 DLL。

## 升级步骤

1. 停止平台或在没有写入时备份完整 `server/data/`，包括 `master.key`。若使用 `PFC_MASTER_KEY`，必须另行保留原值。密钥与数据必须配套恢复。
2. 游戏服按上游说明备份配置并安装 2.6.0 PEAK。将 `verify_token` 设为强随机值：上游要求至少 8 字符，同时包含大写、小写、数字和特殊字符；不要使用出厂值。
3. 在游戏服本地控制台执行 `sldataapi apikey create <id> admin` 或 `duty`。命令返回一次性文件路径，从该文件读取 Key 后保存至平台。遗失的 Key 只能撤销后重建。
4. VerifyToken 用于数据口，API Key 用于控制、事件和语音。二者均由后端通过请求头注入，浏览器不持有游戏服凭据。旧 `controlToken` 存储字段可读取，并在修改配置时迁移；其内容必须已经是有效 API Key，旧式 control_token 本身不能继续鉴权。
5. `control_transport` 选择 HTTP 或 WS。平台只在上游明确返回 `transport_mismatch` 时切换并重试；网络超时、断线、403 或业务失败均不会重放控制操作。看到结果不确定时，先检查游戏内状态或控制审计。
6. 事件流仍需 WS 模式，HTTP 不会补拉历史事件。语音需要上游实际启用语音服务。
7. 广播和管理聊天位于“远程管理”；审计位于“日志 → 控制审计”。admin 默认可用，duty 默认不开放这些权限。审计内容由上游按 Key 授权脱敏。

## 修复与优化

### 控制与长期运行

- 移除控制请求自动重试/断线回退；取消或超时的队列项不会在重连后发送。
- WS 使用标准 `ws` 库处理握手、分片和掩码；增加连接复用、唯一请求 ID、并发上限、消息大小限制、慢消费者断开和心跳清理。
- HTTP / WS 共用路径校验、角色限制及上游 DNS 校验。服务器配置变更会清除旧连接和鉴权冷却。
- WS 在消息到达时、以及最长 30 秒周期内重新校验会话；过期、注销或降权后不能继续执行控制。语音桥每 30 秒复核权限。
- 控制查询缓存按服务器隔离；切服重置当前页面及确认状态；切换账户清空查询、服务器和 WS 内存缓存。
- 上游响应有明确大小和总时限，截断、中断和非 JSON 均报错，不再当作成功空数据。
- 重复订阅复用现有轮询；配置变更后废弃旧 DNS 查询和轮询结果。畸形请求在请求边界关闭，真正的未捕获异常退出进程，由外部守护重启。

### 账户与数据保护

- 2FA 必须先通过密码验证。第二步使用 5 分钟有效、HttpOnly、一次性的 challenge；仅用户名加动态码不能登录。
- TOTP 防重放保存实际验证成功的时间步，重启后仍有效；更换密钥前必须验证并关闭旧配置；解密失败不会跳过 2FA。
- SMTP 保存合并配置，保留管理员引导标记和 Steam Key。
- JSON 解析失败返回服务不可用并保留原文件，禁止默默回退空库后覆盖。原子写入使用受限权限并 flush。
- 邮箱唯一性检查所有账户；防止同一邮箱绑定多个用户名。
- 同源检查覆盖浏览器写请求和 WS 握手；API 响应 `no-store`；公告 Markdown 使用 DOMPurify。
- IPv4-mapped IPv6、展开的回环、链路本地、多播地址不能绕过目标限制；连接固定到已验证 IP，私网按账户当前角色重新校验。

### 界面、性能和维护

- 广播/管理聊天包含上游字段、长度限制、确认和发送反馈；审计支持条数和本地筛选。
- 原生 dialog 提供焦点约束、Esc 取消和忙碌时防误关闭；页面错误边界避免整页白屏。
- 手机顶栏保留服务器、在线状态和人数，较宽屏幕再显示延迟与阶段，避免文字挤成逐字换行。
- 仪表盘 3D 默认关闭、按需加载；打开后在隐藏标签页和减少动态效果模式下停止持续绘制。
- 移除未使用的 drei、ECharts、Gridstack、GSAP；修复 Nodemailer 已知漏洞。
- 静态资源流式传输，支持视频 Range、HEAD、ETag；哈希资源长期缓存，HTML 重新验证，缺失 chunk 返回 404。
- Vite 将全部 `/api`（含 WS）转至正式平台，移除任意 URL 代理。旧 `server/proxy.js` 入口启动同一平台。
- `GET /api/health` 用于部署健康检查，发布仍排除运行数据。该端点证明平台进程可响应，不代表游戏服连接正常。

## 验证与运维

```bash
npm ci
npm ci --prefix server
npm test
npm run build
npm audit --audit-level=high
npm audit --prefix server --audit-level=high
```

测试使用系统临时目录，涵盖账户、2FA、存储、HTTP/WS 契约、取消队列、SSRF 和静态资源。`node scripts/preview-fixture.cjs` 可启动独立模拟游戏服与平台（需要本机私网 IPv4），测试平台仅监听 `127.0.0.1:4317`，不连接真实游戏服。它只用于本机 UI 验收，不能作为生产入口；完成后关闭进程并按输出路径清理临时测试目录。

平台使用 JSON 文件存储，只支持一个写入实例，不要对同一数据目录启动多进程/集群。保留外部备份、进程守护和错误日志。稳定版仍需 Node.js 和依赖的安全维护；以后升级前重复上述检查。

## 回滚

回滚时保留 `server/data/`。人工回滚应使用配套的旧前端、后端及后端锁文件，重新执行 `npm ci --omit=dev --prefix server` 并重启。不要用仅支持旧 control_token 的平台连接 PEAK。数据损坏时停止写入并恢复配套备份，禁止删除 users/config/master.key 来“重新初始化”。

## 验证边界

本地测试和模拟上游覆盖协议、鉴权及界面链路；真实 SCP:SL / LabAPI 的广播显示、管理聊天接收、语音音频、地图操作、插件控制与重启仍需测试服验收。上游 `player/inventory` 与 `dummies` 仍为 501，平台不将其展示为可用功能。
